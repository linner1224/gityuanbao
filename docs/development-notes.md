## 两个关键决策

### 使用静态数据链路

采集器将三个真实 RSS 来源统一写入 `data/news.json`，页面只读取静态 JSON。这样不需要服务器和数据库，GitHub Pages 即可托管；固定夹具也能在断网环境复现解析结果。代价是更新频率受 GitHub Actions 调度影响，实时性不是秒级。

### 分开保存发布时间和采集时间

`publishedAt` 只保存来源给出的原始发布时间，缺失或异常时保持为空；`collectedAt` 单独记录本站采集时间。界面会明确显示“发布时间未知”，不会用采集时间冒充发布时间，满足可追溯与真实性要求。

## 自选亮点

问题是资讯数量较多时，用户很难快速完成当天浏览，也容易反复打开已经看过的内容。项目增加“今日速览”与“已读足迹”：首屏只给 5 条精选资讯和 `1/5` 进度，估算完成时间；点击原文后记录已读状态，并允许隐藏已读。用户可以先完成当天最短阅读路径，再进入完整列表，不需要新增账号或后端。

可信度由“来源透镜”补强。用户点击来源标签即可查看发布时间、采集时间、摘要来源和更新状态；信号雷达则展示中文媒体、海外媒体和官方动态的数量比例。

## 一次问题定位与返工

移动端反馈是固定视频背景“不够清晰”。在 390×844 视口复现后，检查计算样式发现背景容器被放大 1.07 倍，视频自身又放大 1.018 倍，同时叠加 1px 模糊、低亮度和较重遮罩。修复时仅修改 639px 以下规则：移除模糊和视频二次缩放、把背景缩放降到 1.01、提高亮度与对比度，并减轻全屏遮罩。随后在 320、375、390、414 和 768px 验证无横向溢出，正常模式保留清晰视频，减少动态效果模式使用静态海报。
